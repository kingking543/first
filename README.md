# 大乐透号码助手

React + TypeScript + Vite 应用，支持随机选号、规则筛选、生成记录及真实历史开奖统计。生成记录仅保存在当前浏览器中。

## 本地运行与检查

需要 Node.js 20 或更新版本。

```sh
npm ci
npm run dev
npm test
npm run lint
npm run build
npm run check:bundle
```

当前功能无需 API 密钥或环境变量。

## 官方开奖数据

- 来源：[中国体彩网开奖公告](https://www.lottery.gov.cn/kj/kjlb.html?dlt)；采集其公开的大乐透历史接口（gameNo=85）；中央接口不可用时使用[福建体彩网官方历史查询](https://www.fjtc.com.cn/node_309522.htm?gameType=f)页面所用的公开接口。页面按本次成功采集的实际来源显示出处。
- 保留最近 **50 期**真实开奖作为基础数据，列表显示最新 **5 期**；生成器的冷热依据使用完整50期，分析页的出现次数与当前遗漏使用所选的10/30/50期。
- `src/data/official-draws.json` 是已采集的真实快照，包含官方来源、成功核验时间、期号、日期、前区和后区号码。
- `npm run data:update` 从官方接口更新快照。彩种、期号、日期、号码范围、重复号码、连续期号和数据完整性均校验，失败、较旧响应以及重叠期号码/日期不一致均不会覆盖快照。超时、网络错误、408、429 和临时 5xx 最多尝试 3 次，按 1 秒/3 秒退避，Retry-After 最多等待 10 秒；567、401、403 不重试，改为尝试另一官方源。每次超时覆盖请求和响应正文，整体采集最多 120 秒。
- 官方接口的浏览器跨域响应不稳定，因此网页从本站 `data/official-draws.json` 加载数据。Vite 在开发时提供该文件、构建时将同一快照输出到该路径，无需额外后端。
- 页面启动时核对站点数据，允许手动刷新，并在当前浏览器缓存验证过的开奖；加载失败则继续显示已保存的真实数据，明确提示并展示采集时间，不生成模拟开奖。成功读取站点文件不会重置官方核验时间；超过 36 小时未核验时页面显示提醒，每分钟重新判断。以核验时间而非开奖日期判断，避免休市期间误报；设备时间明显早于核验时间会单独提示。
- 完全离线时，前提是页面静态资源已加载；本项目尚未提供离线安装或 Service Worker。

## GitHub Pages 部署与更新

GitHub Actions 在推送到 main、手动触发和每日北京时间计划 **21:45 首次采集、22:15 和 23:15 补采**（首次采集比原来提前30分钟），检查并构建后发布 Pages。代码推送或手动发布时，官方采集失败会输出告警，使用本地与已发布站点中较新的已验证真实快照，保留原始采集时间。定时采集则保持严格失败，让更新问题可见；已部署页面继续可用，可在 Actions 查看失败原因并重试。

发布前还会核对当前已发布站点的快照及它与本地记录的重叠期一致性，防止官方暂时返回旧数据时把线上期号降级；线上基线核验失败会停止部署（首次接入数据路径返回 404 时除外）。

定时采集产生的快照进入部署产物，不会自动提交回 Git。查看线上实际采集时间应以页面显示为准；本地快照可用 `npm run data:update` 更新。Actions 定时任务可能延迟，公共仓库长期无活动也可能被 GitHub 暂停，不能保证开奖后即时更新。

页面所用规则评分仅描述组合符合程度，不参与一组/五组选号，不是中奖概率或预测准确率。

## 代码结构与性能检查

- `src/App.tsx` 组合页面、官方数据和状态钩子；`src/components/` 按生成结果、历史记录、开奖列表及来源信息等职责拆分。
- `src/lib/lotto.ts` 存放可独立测试的选号、评分、历史校验和复制格式。热号排名随统计变化计算一次，仅用于结果评分；五组量化按整批无放回抽样分组。
- `useLottoGenerator` 惰性读取原有 `lotto_history`，保留有效记录并限制 50 条，避免 StrictMode 首次保存覆盖历史；生成与复制定时器在卸载时清理。
- 统计页通过 React.lazy / Suspense 按需加载，图表不进入首页下载；首次加载有占位，模块失败有提示，选号页仍可使用。
- `npm run build` 生成构建清单，`npm run check:bundle` 检查首页 JavaScript < 400 KB、gzip < 140 KB、各分块 < 500 KB，CI 同样执行预算检查。
- TypeScript 启用 strict 和未使用项检查，显式声明 React 类型；移除未使用的 AI SDK、Express、dotenv 和 autoprefixer。

分析模块加载失败时，“重新加载”会刷新页面后重试；生成记录仍保存在浏览器中。

Runner 的采集步骤使用 `--no-network-family-autoselection --dns-result-order=ipv4first`，避免福建官方主机 IPv4/IPv6 竞争时的过短连接超时。来源抓取和重试只在构建脚本执行，不增加浏览器跨域请求或首页依赖。

## 数据分析

分析页可切换最近10/30/50期，显示实际样本数量、起止期号和日期。切换只影响分析页，生成结果的规则符合度仍参考完整50期数据；一组/五组选号不受冷热数据影响。前区高频和当前遗漏前五合并为网格内摘要，同值按号码排序；前后区每个号码均显示出现次数和当前遗漏。当期出现记0期，所选范围内未出现则显示≥N期，不能解释为精确历史遗漏。各区颜色按当前范围的最高次数归一化，仅在同一区内比较。

移除重复频次柱状图与Recharts依赖，分析页仍按需加载；统计期数在切换页面时保留，刷新页面恢复50期。

## 本地与线上开奖同步

本地开发/预览通过localhost、127.0.0.1、IPv6回环或*.localhost打开时，优先请求Vercel实时开奖接口；GitHub Pages也使用该接口，其他正式部署读取自身相对路径，保留项目子路径。请求添加版本参数并禁用浏览器缓存，避免静态CDN沿用旧文件。正式数据端点支持跨域读取。

页面打开、重新可见/获得焦点、网络恢复以及点击刷新开奖时检查更新。自动焦点事件5秒内合并，每次最多一个在途请求，手动刷新不受5秒限制；请求20秒超时。失败或收到较旧/不完整数据时保留本地已验证缓存/随包快照，显示未同步状态，保留原始官方核验时间；不会因本地备份读取成功而伪装线上更新。切换分析期数和生成记录不受同步影响。正常刷新会由Vercel服务端实时查询官方；部署/定时任务继续维护备用快照。

首次计划采集时间为21:45，给[官方21:25开奖](https://www.fjtc.com.cn/node_309449.htm)后的审核发布预留20分钟；这不是对接口发布时间的保证。若官方仍未发布新一期，继续保留已经核验的数据，由后续补采再次检查。上述均为计划触发时间，GitHub Actions可能延迟或未触发，不能视为准点保证。

## 量化增强模式：规则符合度V2

名称、开关与数字评分保留，不增加完全分散开关。量化生成五组时均匀抽取25个不同前区号码、10个不同后区号码，按抽样顺序分组后分别排序，保证组间前区、后区各自无重叠。不得先对整批排序再分组，以免前几组偏向小号。生成一组仍为均匀随机。规则分数和热号不参与一组/五组选号或筛选；关闭量化时仍为独立均匀随机。

底层API对1–6组使用完全分散；7–50组无法保证后区不重叠，保留原V2有界候选池兼容处理。当前页面只提供一组和五组。分散仅约束同批，不排除跨次生成或与历史记录重复。

公平独立开奖下，完全分散达到五组“至少一注中任意奖”的最大概率约32.28%，任意奖包含最低奖；这不提高单注或五组不同完整组合的头奖概率，也不代表回本。证明与精确计数见[补充研究报告](reports/coverage-optimum-2026-11-11/report.md)。

规则符合度为组合形态75分、历史参考5分和组间分散20分的四舍五入总分。组间分散按最终整批计算，单组按20分计。分数表示规则符合程度，不是中奖概率。新记录保存scoreVersion2，历史分数保持原值并标注旧规则，不随历史开奖变化重新计算。

旧回测原算法冻结于scripts/research/baseline-lotto.ts；V2完整源码冻结于scripts/research/baseline-v2/，V3研究中的currentV2/v2NoHistory引用冻结版本，200个已归档固定批次数值可复现。旧报告清单里的生产源码哈希对应该V2快照，不应再用更新后的生产文件冒充旧基线。规则评分公式和scoreVersion2保持不变，历史记录不重算。

## Vercel 开奖数据同步

Vercel 使用 `vercel.json` 指定的 `npm run build -- --mode vercel` 构建。该模式保留页面内的已核验备份，但不输出 `/data/official-draws.json` 静态文件，避免文件系统优先级遮盖实时接口。普通构建和 GitHub Pages 继续输出原静态快照。

Vercel 将同域 `/data/official-draws.json` 路由到 `api/official-draws.ts`（Node.js Web API）。服务端并行查询中央与福建官方源，并读取Pages备用快照；官方请求总预算8秒，备用读取最多3秒。对50期、审核标志、连续期号、日期和重叠号码核验后选较新官方结果，不会因为一个健康源仍是旧期而忽略另一源的新期。两个有效官方源互相冲突时保留备份，不将任一冲突结果标为已核验。

实时结果在兼容的扁平JSON中增加 `verification: official`；官方失败时返回 `verification: snapshot` 和原始核验时间，绝不把读取备份时间当作官方核验时间。浏览器仍防降级、检查重叠一致性并保留更新的本地缓存；接口不可用时还会尝试Pages静态备份。来源区明确区分实时核验成功与备份状态。

公开只读接口支持GET/HEAD/OPTIONS及跨域读取；Pages和本地开发均可调用，不引入密钥、数据库或进程内持久缓存。响应和CDN均禁用缓存，保留版本参数。函数最长30秒，客户端请求上限20秒；故障后继续保留已保存数据。浏览器生成与统计功能不依赖接口成功。

“刷新开奖”现在会在服务端向官方核验，GitHub定时任务仍维护快照，但漏触发不再是获取新开奖的唯一阻断点。首次启用需要部署新接口；后续官方数据变化无需重新构建Vercel页面。官方接口本身不可用时仍无法保证立即取得新期，界面会显示备份状态，保留真实核验时间。
